# Release v2.6.0.69

**Date**: 2026-11-10  
**Git Tag**: `v2.6.0.69`  
**Domain**: Laboratory Information System (LIS), Specimen Accessioning, Sequential Auto-Increment, Collision Guards, Lab Number Search  

---

## Overview

Release `v2.6.0.69` delivers a major overhaul of the **Medical Laboratory Workbench (LIS)** specimen numbering and accessioning pipeline, resolving persistent cross-patient duplicate lab number collisions and sequence regressions, introducing lab number patient lookup, and displaying accession identifiers across all queues, cards, and datatables.

## Key Enhancements

1. **Collision-Free Sequential Auto-Increment (`calculateNextLabNumber`)**:
   - Eliminated the `orderBy('id', 'desc')` order-of-creation flaw that caused sequential regression whenever older investigation orders were sampled late.
   - Detects the facility's active lab numbering family (`LAB{YY} - #####` or `LAB-#####`), extracts the true maximum sequence integer, and executes an exhaustive whitespace-normalized collision avoidance verification loop (`REPLACE(lab_number, ' ', '') = ?`) against the entire database.
   - Pre-checks whether the selected patient already has an active sample accession from today and provides a 1-click option to reuse their active accession number or generate the next sequential identifier.

2. **Server-Side Collision Rejection & Accession Governance**:
   - `collectSample()` enforces database-level cross-patient uniqueness: attempting to assign a lab number that belongs to another patient immediately aborts with `422 Unprocessable Entity` (`"Lab number is already assigned to [Patient]..."`).
   - Multiple test requests belonging to the same patient during an accession session continue to cleanly share their assigned accession barcode.
   - Real-time client-side duplicate detection (`checkLabNumberExists`) provides immediate visual alert states (red collision alert blocking submission vs. info notice for same-patient session grouping).

3. **Sample Collect Button State Restoration**:
   - Resolved stuck spinner states (`"Collecting..."`) on sample collection by adding a guaranteed `complete:` AJAX lifecycle callback.
   - Wired Bootstrap `hidden.bs.modal` event listener on `#sampleCollectionModal` to restore button text, clear input states, and reset pending sample IDs on close, cancel, or submission.

4. **Workbench-Wide & Global Patient Search by Lab Number**:
   - Enhanced both `LabWorkbenchController::searchPatients()` and unified `PatientSearchController::search()` to query `LabServiceRequest` by `lab_number` across formatted (`LAB26 - 11629`), unformatted (`LAB26-11629`), space-less/dash-less (`LAB26 11629`), and numeric sequence tokens.
   - Updated `@include('admin.partials.patient_search_html')` to support contextual routing and parameters (`$route`, `$search_context`, `$placeholder`).
   - `PatientSearchWidget` dropdown displays a distinct `Lab# <number>` badge in search meta items for matched patients and forwards search context parameters.
   - Laboratory Reports patient filter now searches `lab_number` directly alongside file number and name.

5. **Prominent Lab Number Visibility Across Lists & DataTables**:
   - **Queue DataTable (`#queue-datatable`)**: Queue item cards show a prominent monospace `Lab#` badge in the header row beside the patient file number.
   - **Patient Header Ribbon**: Displays active `Lab#: <badge>` in `#patient-meta` at the top of the patient workspace.
   - **Workspace Request Cards**: Test cards in Billing, Sample Collection, Results, and Approval tabs clearly show `Lab#` badges in titles and card metadata.
   - **Approval Queue & Detail Review Modal**: Consultant verification queue API and modal detail review view expose the assigned Lab Number.
   - **Lab Reports DataTable (`#reports-datatable`)**: Added a dedicated `Lab No` column with search and export visibility.
   - **Deleted & Dismissed Modals**: Trash inspection cards display the Lab Number.
